# 小信号 INTERACTIONS V1

## 1. 文档目的

本文件定义“小信号”微信小程序的核心交互规则。

它负责回答：

- 用户点击后发生什么
- 用户双击后发生什么
- 用户长按后发生什么
- 页面如何跳转
- Bottom Sheet 如何出现与关闭
- Toast 如何反馈
- 动画如何触发
- 震动何时发生
- 异常状态如何处理
- 权限拒绝后如何降级
- 关系状态变化后页面如何响应

本文件与以下文档配合使用：

- `PRD.md`
- `UI_SPEC.md`
- `DESIGN_SYSTEM.md`
- `DATA_MODEL.md`
- `ACCEPTANCE.md`

如交互逻辑与视觉规范冲突：

业务行为以本文件为准，视觉表现以 `DESIGN_SYSTEM.md` 为准。

---

# 2. 全局交互原则

## 2.1 核心动作必须轻

核心信号发送尽量控制在：

```text
1～2 个动作
2 秒左右
```

禁止增加无必要确认步骤。

例如：

```text
点击信号
→ 立即发送
```

而不是：

```text
点击信号
→ 弹确认框
→ 再点确认
→ 发送
```

---

## 2.2 不制造回复压力

所有信号都不是聊天消息。

禁止：

- 已读回执压力
- “TA 已读但未回复”
- 催回复
- 回复倒计时
- 红色未读数字轰炸

---

## 2.3 不强行引导关系行为

系统不得主动提示：

```text
快去关心 TA
快去哄 TA
你们已经很久没说话了
TA 可能不开心
```

可以中立展示状态，但不能替用户解释关系。

# 9. Signal Orb 单击

## 行为


---

# 10. Signal Orb 双击

## 触发

两次点击间隔建议：

```text
<= 300ms
```

## 行为

直接发送：

```text
SignalType = knock
```

不打开 Signal Picker。

## 反馈

```text
轻震一次
→ Orb 波纹
→ Toast：已敲一下
```

## 防冲突

单击需要短暂等待双击判定。

推荐：

```text
第一次 tap
↓
等待约 220～280ms
↓
若无第二次 tap
→ 打开 Picker
```

---

# 11. Signal Orb 长按

## 触发

长按阈值建议：

```text
>= 450ms
```

## 行为

显示：

`Quick Signal Wheel`

## 长按状态

手指未松开时：

- 中央 Orb 进入 pressed 状态
- 周围信号项淡入
- 当前手指方向对应项高亮

## 手指移动

根据触点相对 Orb 中心角度判断目标信号。

## 松手

如果已选中有效信号：

立即发送。

如果没有进入任何有效区域：

关闭 Quick Signal Wheel，不发送。

# 15. 发送中状态

发送中：

- 禁止重复点击同一信号
- Orb 进入发送动画
- 主按钮暂时不可再次触发

建议最大等待：

```text
3000ms
```

超时进入失败状态。

---

# 16. 发送成功

## 动画

```text
Orb 缩小
→ 波纹扩散
→ 恢复
```

## 震动

调用一次：

轻震。

## Toast

例如：

> 信号已经送出

若明确收到对方设备确认：

> 对方已经收到

但不得显示：

> 对方已读

除非产品未来正式定义。

# 17. 发送失败

页面原地显示：

```text
还没有送出去
```

操作：

```text
再试一次
稍后发送
```

---

## 点击「再试一次」

重新调用发送。

保持原 Signal 内容。

---

## 点击「稍后发送」

将该 Signal 放入本地待处理状态。

注意：

网络恢复后不得自动发送。

恢复网络时提示：

> 有一个信号还没有送出

操作：

```text
现在发送
丢弃
```

避免过时情绪自动送达。

# 44. Toast 规则

Toast 用于：

- 成功
- 轻提示
- 非阻塞错误

不要用于：

- 严重错误
- 需要用户选择的操作

默认时长：

```text
1500～2500ms
```

---

# 45. Confirm Sheet 规则

仅用于高风险操作：

- 删除暗号
- 删除照片
- 删除胶囊
- 解除关系
- 注销账户

普通发送信号不得使用确认弹窗。

---

# 46. Loading 规则

请求 < 500ms：

尽量不显示 Loading。

请求 > 500ms：

显示轻量呼吸状态。

不要在页面中心放大型旋转菊花。

---

# 47. Offline 状态

全局检测网络变化。

断网时：

可显示弱提示：

> 当前网络不可用

不强制弹窗。

当用户执行发送操作时：

才进入明确失败状态。

---

# 48. 权限拒绝状态

适用于：

- 相册
- 相机
- 通知

必须说明：

- 为什么需要
- 拒绝后影响什么
- 用户仍可以做什么

例如：

> 无法访问相册，因此暂时不能发送照片信号。普通信号仍可正常使用。

---

```text
轻微缩放
圆点靠近
卡片上浮
```

禁止新增与产品气质冲突的：

- 烟花
- 彩纸
- 强弹跳
- 大爱心
- 复杂粒子爆炸

---

# 55. 震动统一规则

仅以下动作建议震动：

```text
发送成功
收到信号（应用前台）
接住成功
双击敲一下
```

使用轻震。

同一流程不得连续多次震动。

---

# 56. 深色模式

系统主题变化时：

页面应实时响应或下次进入时正确加载。

Signal Orb Glow 需要降低强度，避免黑底刺眼。

---

# 57. 页面离开保护

以下页面有未提交内容时需要保护：

```text
照片信号
时光胶囊创建
暗号创建/编辑
```

用户返回时：

若有实质内容，弹出：

> 还没有保存，要离开吗？

按钮：

```text
继续编辑
离开
```

普通页面不弹。

---

# 58. 数据刷新

首页进入：

刷新：

- partner
- mood
- 未接信号

足迹进入：

刷新最近数据。

不要求所有 Tab 每次都全量重新加载。

---

# 59. Mock 阶段交互要求

在未接真实后端前：

所有交互仍必须可完整模拟。

例如：

```text
发送 Signal
↓
Mock Repository 保存
↓
切换 Mock 用户
↓
看到 Signal
↓
回应
↓
切回发送者
↓
看到回应
```

不得只做静态页面。

---

# 60. 核心闭环验收

最重要流程：

```text
用户 A
↓
打开首页
↓
点击 Signal Orb
↓
选择「想到你了」
↓
发送成功
↓
用户 B 收到
↓
用户 B 点击「接住了」
↓
用户 A 看到回应
```

该流程必须覆盖：

```text
normal
loading
success
error
offline
duplicate tap
```

只有完整闭环稳定运行，才算核心交互完成。
